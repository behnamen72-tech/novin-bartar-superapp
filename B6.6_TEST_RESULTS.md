# B6.6 Test Results — People & User Management UI

Baseline: B6.5 Organization Management package.

## Backend regression

B6.6 reuses the B5.6 People/User write APIs and adds one additional self-lockout
safeguard: an administrator cannot deactivate the Person record attached to their
own active account through the Person status endpoint.

Executed against the cumulative package:

- `pytest -q`: **103 passed**
- `python -m compileall -q app tests scripts`: **passed**
- OpenAPI generation with isolated SQLite configuration: **48 paths**
- Alembic PostgreSQL offline SQL through migration `20260910_0012`: **passed**

The new backend regression test verifies that self-Person deactivation returns
`409` and leaves the Person active.

## Frontend deterministic checks

- B6.3 navigation: **12 assertions passed**
- B6.4 dashboard: **11 assertions passed**
- B6.5 organization management: **18 assertions passed**
- B6.6 people/user management: **37 assertions passed**

B6.6 coverage includes:

- `people.manage` and `users.manage` scope calculations are UX-only helpers
- descendant scope vs self-only scope behavior
- shared-Person global edit affordance requires all visible relevant orgs to be manageable
- eligible Person filtering for User creation
- optional text / username normalization
- every new unsafe People/User BFF route uses `proxyAuthenticatedRequest()`
- Person relationship status routing preserves person/relationship identifiers
- User password-reset route remains inside the authenticated BFF
- current User self-deactivation and current Person self-deactivation affordances are disabled in UI
- password confirmation and new-password autocomplete behavior
- Person relationship id/start/end fields are represented in frontend types

## TypeScript verification

the globally available TypeScript compiler API:

- files parsed: **50**

A temporary declaration shim for unavailable React/Next dependency types was used

without real React JSX declarations the temporary intrinsic-element shim cannot

This is not claimed as a substitute for the dependency-installed Next.js typecheck.

`npm install --ignore-scripts --no-audit --no-fund --prefer-offline` was attempted
in the isolated runtime but did not complete before the execution timeout and did
not create `node_modules`.

Therefore these are **not** claimed as passed here:

- `npm run typecheck` with real React/Next package types
- `npm run lint`
- `npm run build`

Run them in the normal local development environment after dependency installation.

## Security/integration checks

Verified in source and tests:

- no new browser route receives backend access/refresh token values
- all People/User mutations travel through the centralized authenticated BFF
- B6.2 CSRF/origin protection therefore remains in the write path
- frontend permission/scope calculations only hide/show controls; FastAPI services re-authorize every mutation
- shared Person writes remain protected by backend multi-organization authorization
- relationship deactivation still fails if active access assignments are rooted at that relationship organization
- User create/edit/status/password reset still use `users.manage` and backend dominance checks
- raw password/hash is never included in API responses or Audit payloads
- password form state is cleared when the User dialog closes or submission completes/fails
- User self-deactivation remains blocked
- Person self-deactivation is now also blocked to prevent indirect session/access lockout
