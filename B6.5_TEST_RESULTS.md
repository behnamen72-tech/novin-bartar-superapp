## Security/integration checks

Verified in source and tests:

- all organization mutations require authenticated BFF requests
- unsafe BFF routes reuse the B6.2 centralized CSRF/origin guard
- frontend scope logic is affordance-only and is never trusted by FastAPI
- server-side B5.6 `organization.manage` authorization remains authoritative
- inactive-target recovery reuses `has_permission_including_inactive_target()` rather than adding a parallel scope model
- root Holding status is bootstrap-only, preventing a public-API self-lockout condition
- `parent_id` and `organization_type` remain immutable through the generic update API
- no browser-accessible access/refresh token handling was introduced
